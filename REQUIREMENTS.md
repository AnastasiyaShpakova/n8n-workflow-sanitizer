# Спецификация требований: n8n Workflow Sanitizer

## 1. Назначение проекта

n8n Workflow Sanitizer - локальный инструмент для предварительной проверки и обезличивания экспортированных JSON workflow n8n перед публикацией в открытых репозиториях.

Цель - снизить риск случайного раскрытия конфиденциальных данных, сохранив структуру workflow и предоставив пользователю отчёт для окончательной ручной проверки.

Инструмент не гарантирует абсолютную безопасность публикации.

## 2. Функциональные требования

### 2.1. Ввод и вывод

- **FR1:** Принимать стандартный JSON-файл, экспортированный из n8n, через локальный веб-интерфейс.
- **FR2:** Генерировать обработанный JSON workflow для скачивания. Имя выходного файла может содержать временную метку.
- **FR3:** Генерировать Markdown-отчёт с результатами маскирования, предупреждениями и нерешёнными рисками.
- **FR4:** Не раскрывать исходные секреты в отчёте.
- **FR5:** Не изменять исходный входной файл.

### 2.2. Обнаружение и маскирование

- **FR6:** Использовать два подхода к обработке потенциально конфиденциальных данных:
  - Автоматически маскировать значения, уверенно распознанные как секреты.
  - Помечать неоднозначные значения для ручной проверки, если автоматическая замена может нарушить работу workflow.
- **FR7:** Сохранять технические идентификаторы нод, имена нод и структуру соединений.
- **FR8:** Сохранять корректность выражений n8n и JavaScript-кода, не изменяя их без обоснованной необходимости.
- **FR9:** Предупреждать пользователя, что нестандартные секреты могут остаться необнаруженными.
- **FR10:** Обезличивать распознанные идентификаторы и названия объектов `credentials`, а также отдельные инфраструктурные идентификаторы.
- **FR11:** Сохранять `webhookId` для совместимости импорта в n8n, отмечая его как нерешённый риск публикации.
- **FR12:** Обнаруживать опасные настройки, включая `allowUnauthorizedCerts: true`, и отражать их в отчёте.

### 2.3. Интерфейс

- **FR13:** Предоставлять локальный веб-интерфейс на Flask.
- **FR14:** Использовать русскоязычный одностраничный интерфейс.
- **FR15:** Обеспечивать загрузку JSON и скачивание обработанного workflow и отчёта.
- **FR16:** Отображать статистику обнаруженных и замаскированных значений, предупреждений и нерешённых рисков.

### 2.4. Обработка ошибок и проверка целостности

- **FR17:** Проверять корректность входного JSON и сообщать об ошибках формата.
- **FR18:** Обрабатывать отсутствие файла и загрузку пустого файла.
- **FR19:** Корректно сообщать, если распознанные секреты не обнаружены.
- **FR20:** Проверять сохранение количества нод, структуры соединений и значимых выражений n8n.
- **FR21:** Не обозначать результат как готовый к публикации при наличии нерешённых рисков.

## 3. Нефункциональные требования

- **NFR1. Приватность:** Обработка должна выполняться локально, без передачи содержимого workflow на внешние серверы. Отсутствие внешней сетевой активности требует отдельной проверки.
- **NFR2. Минимализм:** Минимальное количество зависимостей. Без внешних LLM, API и баз данных в процессе обработки.
- **NFR3. Производительность:** Целевое время обработки типового workflow - менее двух секунд. Выполнение требования должно подтверждаться измерениями.
- **NFR4. Совместимость:** Обработанный JSON должен сохранять возможность импорта в n8n. Работоспособность подключений после импорта требует отдельной настройки и проверки.

## 4. Основные риски

**Риск 1. Избыточное маскирование**

Замена технических идентификаторов или выражений может нарушить работу workflow.

**Риск 2. Недостаточное маскирование**

Нестандартные секреты могут остаться в итоговом JSON.

**Риск 3. Повреждение структуры**

Некорректная обработка может изменить ноды, соединения или выражения n8n.

**Риск 4. Публикация webhookId**

Сохранённые идентификаторы webhook могут представлять риск раскрытия информации. Необходима ручная проверка.

**Риск 5. Ложное ощущение безопасности**

Отсутствие обнаруженных секретов не означает, что файл безопасен для публичного размещения.
